## What's New

- Fixed APRS-IS outbound messages getting permanently stuck in the send queue.
- Fixed received APRS message IDs appearing as trailing garbage characters in the message pane.
- Corrected tocall field: all outbound frames now use `APZWLF` instead of the placeholder `APRS`.

## User-Facing Changes

- Fixed:
  Messages sent via APRS-IS now leave the queue and advance to `sent` / `acked` state. Previously they remained queued indefinitely.
- Fixed:
  Received messages no longer show trailing `{xx}` APRS message ID suffixes in the message pane (e.g. `{ET`, `{04`, `{NM` are now stripped from the displayed body).
- Fixed:
  All outbound APRS frames (TNC and APRS-IS, messages and ACKs) now carry the correct tocall `APZWLF` per APRS tocall conventions. The placeholder value `APRS` is no longer used.

## Upgrade Notes

- Settings and outbound queue files from v0.32.0 remain fully compatible.
- Any messages left in the queue from v0.32.0 that used APRS-IS will be retried automatically on first launch.
